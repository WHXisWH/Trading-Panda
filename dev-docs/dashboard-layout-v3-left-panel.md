# Dashboard 左栏合并方案 v3（设计稿）

> **状态**：已实现（2026-05-25） · **日期**：2026-05-25  
> **前置**：`dashboard-layout-v2.md`（主区决策底栏、右栏策略、方案 A 池订阅）  
> **本次目标**：将 **模拟账户** 并入 **「我的熊猫」** 左栏，形成单一「训练体侧栏」；右栏专注策略积木。

---

## 1. 设计动机（为什么合并）

| 现状问题 | 合并后的收益 |
|----------|----------------|
| 账户在右栏、熊猫在左栏，用户要在两侧扫视才能回答「这只熊猫赚了多少」 | **一眼完成**：身份 + 盈亏同属「我的训练会话」 |
| 右栏同时塞账户 + 策略，垂直空间紧张，策略编辑区被账户挤短 | 右栏 **100% 给策略积木**，编辑体验更好 |
| `AccountPanel` 与 `PandaSidebar` 两套卡片样式、两个「训练中」状态 | **一个容器、一套分隔线**，视觉更整 |
| 平板/手机在主区重复渲染账户（`xl:hidden` 副本） | 合并后 **单一数据源、单一挂载点**，响应式更简单 |

**产品叙事（用户心智）**  
Dashboard 不是「行情软件 + 旁边挂个宠物」，而是 **「我在看一只熊猫替我练盘，顺便看它的成绩」**。账户本质是 **这只熊猫的模拟盘账本**，放在熊猫卡片下方比放在行情右侧更自然。

## 3. 合并组件：`DashboardPandaPanel`（推荐命名）

> 实现时可由 `PandaSidebar` 演进，或新建后 Dashboard 专用；**非 Dashboard 页面**（若有复用）仍保留原 `PandaSidebar`。

### 3.1 信息架构（自上而下）

```
┌─────────────────────────────────────┐
│ A. 身份区 Identity                   │  固定，不滚动
│    头像 · 名字 · 阶段/熟练度          │
│    情绪 · 经验条 · 天赋               │
│    五轴雷达 120px                    │
├─────────────────────────────────────┤
│ B. 账本区 Ledger                     │  随训练刷新
│    标题行：模拟账户 + 训练状态点       │
│    权益（主数字）+ 盈亏着色            │
│    持仓（当前 primary pool）          │
│    成交笔数                          │
│    [展开详情 ▼] 初始资金/仓位占比…     │  默认折叠，减噪
├─────────────────────────────────────┤
│ C. 操作区 Actions                    │  固定底或跟随滚动末
│    冷静竹 · 切换熊猫 · 管理交易池      │
└─────────────────────────────────────┘
```

### 3.2 字段映射（数据契约）

| UI 区块 | 数据来源 | 刷新 |
|---------|----------|------|
| 身份五轴/雷达 | `PandaDetailApi` | 低 |
| 情绪/经验 | `panda.emotion_state` / `experience_level` | WS `emotion`（间接展示，无数值） |
| 权益/持仓/笔数 | `AccountPanelSnapshot`（现有） | `simulation/status` 2s + WS `trade` |
| 当前池（持仓行） | `snapshot.pool`（与 Chart 同步） | 用户 ChartHeader 切池 |
| 训练状态 | `snapshot.training` | 与 TrainingBar 一致 |

**Props 建议（单一入口）**：

```typescript
interface DashboardPandaPanelProps {
  panda: { /* 现有 PandaSidebar 字段 */ };
  account: AccountPanelSnapshot;
  pandas?: { id; name }[];
}
```

页面层继续组装 `accountSnapshot`，只改 **挂载位置**。

### 3.3 视觉规范（Obsidian tokens 对齐）

| 元素 | 规格 |
|------|------|
| 外容器 | 单张 `bg-paper-card` · `rounded-xl` · `p-3` · **无嵌套第二张账户卡片** |
| A/B 分隔 | `border-t border-[var(--color-border)]` + `pt-3` · 小标题 `模拟账户` 11px `text-ink-500` |
| 权益主数字 | `font-mono` · 15–17px semibold · 盈亏 `%` 用 `text-profit` / `text-loss` |
| 训练状态 | 与 TrainingBar 统一：绿点 +「训练中」/ 灰点「未训练」；**仅账本区标题行显示一次** |
| 雷达 | 保持 **120px**（你已确认） |
| 折叠详情 | Radix Collapsible 或纯 CSS；默认收起 `初始资金`、`参考价`、`仓位占比` |

### 3.4 交互规则

1. **切池（ChartHeader）** → 账本区「持仓」行即时更新 `pool` / 数量（已有 `handlePoolChange` 逻辑）。
2. **训练中** → 权益数字可做 subtle pulse（可选，Phase 2）；MVP 仅数值刷新。
3. **未持仓** → 持仓行显示 `—`，不隐藏整块账本区（保持布局稳定）。
4. **切换熊猫** → 整页路由 `/dashboard/[id]`，账户随新 panda 的 simulation 重拉。
5. **「管理交易池」** → 保留在操作区；TrainingBar 的「管理交易池」**保留**（快捷入口），两处文案一致即可。

## 5. 栅格与 Token（CSS）

```css
/* ≥1280px 三栏 */
grid-template-columns:
  minmax(0, clamp(220px, 20vw, 280px))   /* 左：合并后略宽 */
  minmax(0, 1fr)
  minmax(0, clamp(260px, 24vw, 300px)); /* 右：仅策略 */
```

| Token | 建议值 | 说明 |
|-------|--------|------|
| `--dashboard-left-min` | 220px | 合并后最少容纳雷达+权益行 |
| `--dashboard-left-max` | 280px | 弹性上限 |
| `--dashboard-strategy-min` | 260px | 右栏策略 |

左栏 **sticky + 内部滚动**（仅当 A+B+C 总高超过视口时，C 或 B 区滚动，A 区建议 sticky top 在侧栏内——实现期二选一：**整栏滚动** 更简单，MVP 推荐整栏 `overflow-y: auto`）。

## 6. 响应式

| 断点 | 布局 | 合并面板 | 策略 |
|------|------|----------|------|
| **&lt;1024** | 单列 | 顺序：**训练条 → K线 → 合并面板 → 决策历史** | 底部「编辑策略」抽屉 |
| **1024–1279** | 两栏：左合并面板 \| 主栏 | 左侧 sticky | 底部抽屉 |
| **≥1280** | 三栏 | 左合并面板 | 右栏策略 |

**删除** v2 中主栏内的 `DashboardAccountAside`（`xl:hidden` 副本），避免重复。

小屏合并面板：

- 雷达可保持 120px 或缩至 96px（&lt;640px 时可选）
- 账本区「展开详情」默认收起，保证首屏能看到 K 线
