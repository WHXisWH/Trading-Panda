## 3. Backend — Python Decision Engine

### 3.1 Process model

```
FastAPI process (single)
│
├── HTTP API handlers (async)
│   ├── POST /auth/login          — wallet address → JWT
│   ├── GET  /auth/me             — decode JWT → user
│   ├── GET  /pandas              — list user's pandas
│   ├── POST /pandas              — register panda after on-chain mint
│   ├── GET  /pandas/{id}         — single panda + active strategy
│   ├── GET  /pandas/{id}/strategy
│   ├── POST /engine/strategy/parse  — DeepSeek parse → store in DB
│   ├── POST /engine/actors/{id}/start
│   ├── POST /engine/actors/{id}/stop
│   └── GET  /engine/actors/{id}/state
│
└── asyncio Task per PandaActor (up to MAX_ACTORS = 100)
    └── subscribes to Redis channel: market:{asset}
    └── on each tick: runs 8-step DecisionPipeline
```

### 3.2 8-step Decision Pipeline

Each step runs under 50ms total:

| Step | Name | Description |
|---|---|---|
| S1 | Strategy signal | Parse signal from active strategy rules (RSI, MACD, etc.) |
| S2 | Proficiency noise | Add Gaussian noise inversely proportional to proficiency level |
| S3 | Experience correction | Apply pattern memory and cycle wisdom corrections |
| S4 | Signal fusion | Weighted merge of strategy signal + experience corrections |
| S5 | Personality filter | Apply boldness (entry threshold), patience (delay), contrarian (inversion) |
| S6 | Environment adaptation | Adjust for market regime × asset mastery score |
| S7 | Social bias | Ghost weight from previous strategy (decays over time) |
| S8 | Emotion distortion | Apply emotion coefficient; greedy amplifies, panicking suppresses |

Final score routing:
- `> 0.65` → execute trade immediately
- `0.40 – 0.65` → ambiguous; call LLM Agent Coordinator (3s timeout, falls back to HOLD)
- `< 0.40` → ignore signal

### 3.3 Emotion State Machine

7 states with deterministic transitions:

```
focused  ──(win streak ≥ 3)──► excited  ──(win streak ≥ 5)──► greedy
   ▲                                                              │
   │ calm_bamboo                                         (any loss)
   │                                                              ▼
numb ◄──(idle ≥ 10 ticks)── cautious ◄──(single loss > 5%)── cautious
                                │
                    (drawdown > 10%)
                                ▼
                           panicking
```

Emotion coefficients applied at Step 8:
| State | Coefficient |
|---|---|
| focused | 1.00 |
| excited | 1.10 |
| greedy | 1.30 |
| cautious | 0.85 |
| panicking | 0.50 |
| numb | 0.60 |

Special: talent = 1 (竹林禅心) prevents transition to panicking.

## 4. Database — 18 Tables

```
users               — wallet_address, zk_login_subject, onboarding_survey
pandas              — sui_object_id, owner_id, personality axes, emotion_state
strategies          — panda_id, raw_text, parsed_json (4-layer), strategy_hash
strategy_history    — panda_id, strategy_id, event_type (activated/deactivated)
simulations         — panda_id, strategy_id, status, equity, trade_count
trades              — panda_id, strategy_id, simulation_id, action, final_score, decision_details (JSONB)
experience_patterns — panda_id, pattern_type, confidence
experience_mastery  — panda_id, asset, mastery_score (unique per panda+asset)
experience_mistakes — panda_id, trade_id, mistake_type, penalty
experience_cycles   — panda_id, cycle_type (bull/bear/sideways), performance_data
emotions_log        — panda_id, from_state, to_state, trigger
merkle_roots        — panda_id, root_hash, trade_count, batch_index, sui_tx_digest
achievements        — code, title, description, requirement_json
user_achievements   — user_id, panda_id, achievement_id (unique per user+achievement)
checkins            — user_id, streak_count, checkin_date (unique per user+date)
market_data_cache   — asset, timeframe, data JSONB (unique per asset+timeframe)
correlation_matrix  — asset_pair, correlation
panda_diary         — panda_id, content, trade_id, emotion_state
```

All primary keys are UUIDs. Timestamp columns use `timezone=True`.

Tables are created automatically on backend startup via `Base.metadata.create_all`.

## 6. Auth Flow

```
1. User connects Sui wallet (ConnectButton from @mysten/dapp-kit)
2. Frontend calls useSignPersonalMessage("TradingPanda:login:{timestamp}")
3. POST /api/auth/wallet-login { wallet_address, message, signature }
4. Next.js proxies to Python POST /auth/login
5. Python upserts User row in PostgreSQL
6. Python issues JWT (HS256, 7-day expiry, secret = JWT_SECRET env)
7. Frontend stores JWT in Zustand (persisted to localStorage)
8. All subsequent API calls: Authorization: Bearer {jwt}
```

Note: signature verification is skipped in MVP (wallet_address trusted). Production should verify via pysui.
