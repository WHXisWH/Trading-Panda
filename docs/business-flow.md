## 4. Simulation Loop (Per Tick)

```
Redis channel: market:tick:{pair}   （频道契约见 docs/redis-architecture.md §5）
       │
       │  MarketEvent { price, volume, timestamp, indicators }
       ▼
PandaActor._tick(market_data)
       │
       ▼
DecisionPipeline.run(personality, strategy, emotion, experience, market_data)
       │
       ├── Step 1: strategy signal         → raw_signal
       ├── Step 2: proficiency noise       → noisy_signal
       ├── Step 3: experience correction   → corrected_signal
       ├── Step 4: signal fusion           → fused_signal
       ├── Step 5: personality filter      → personality_signal
       ├── Step 6: environment adaptation  → adapted_signal
       ├── Step 7: social bias (ghost)     → biased_signal
       └── Step 8: emotion distortion      → final_score
                   │
                   ▼
          ┌────────────────────┐
          │  final_score > 0.65│──► execute trade
          │  0.40 – 0.65       │──► call LLM Agent Coordinator (3s timeout)
          │  < 0.40            │──► ignore
          └────────────────────┘
                   │ (if execute)
                   ▼
          INSERT trades row
          UPDATE panda equity
          UPDATE simulation stats
          EmotionStateMachine.update(trade_result)
          ExperienceEngine.update(trade_result)
          │
          └── every 50 trades:
                MerkleWorker.compute_root(last_50_trade_hashes)
                submit_merkle_root to Sui chain
                INSERT merkle_roots row
```

## 5. Emotion State Machine

States and transition triggers:

```
                    calm_bamboo item used
                    ┌──────────────────────────────────────────┐
                    │                                          │
                    ▼         win_streak ≥ 3                  │
              [ focused ] ──────────────────► [ excited ]     │
                  ▲ ▲         win_streak ≥ 5                  │
                  │ │   ┌─────────────────────► [ greedy ]    │
                  │ │   │ any single loss                      │
                  │ │   │         ┌───────────────────────────┘
                  │ │   └─────────┘
                  │ │
                  │ └── calm_bamboo
                  │
              [ numb ] ◄── idle ≥ 10 ticks ──────────────────────────────┐
                                                                          │
              [ cautious ] ◄── single loss > 5% ────────────────────────┐│
                  │                                                      ││
                  │  drawdown > 10%                                      ││
                  ▼                                                      ││
          [ panicking ] ──────────────────────────────────────────────────┘│
              │                                                            │
              │  (talent=1 竹林禅心 blocks transition to panicking)         │
              └─── idle ≥ 10 ticks ──────────────────────────────────────┘
```

Emotion is stored in `pandas.emotion_state` (PostgreSQL) and pushed to frontend via WebSocket (pending implementation).

## 6. Experience Accumulation

The Experience Engine maintains 5 sub-systems, all stored in PostgreSQL:

| Sub-system | Table | What it tracks |
|---|---|---|
| Pattern memory | `experience_patterns` | Market pattern hash → win rate at that pattern |
| Asset mastery | `experience_mastery` | Trade count + success rate per asset (BTC/ETH/SUI) |
| Mistake journal | `experience_mistakes` | Repeated errors (chasing highs, panic selling) |
| Cycle wisdom | `experience_cycles` | Behaviour during bull / bear / sideways markets |
| Diary | `panda_diary` | LLM-generated narrative entries per significant trade |

Experience level (0–100) is computed from the above and stored in `pandas.experience_level`.

Milestone events (level 25 / 50 / 65 / 80 / 100) emit `MilestoneEvent` on-chain via `experience.move`.

## 7. Merkle Root Trust Flow

```
Decision Engine records each trade:
  leaf_data = {
    timestamp, panda_id, strategy_hash,
    market_data_hash, raw_signal, final_score, action
  }
  leaf_hash = SHA-256(leaf_data)

Every 50 trades:
  tree[0] = leaf hashes
  tree[i+1] = SHA-256(tree[i][2k] || tree[i][2k+1])
  root_hash = tree[top][0]

  submit_merkle_root(
    panda_id, root_hash, trade_count=50,
    batch_index, timestamp
  ) → Sui transaction

  INSERT merkle_roots { root_hash, batch_index, sui_tx_digest }

Anyone can verify a specific trade by:
  1. Fetching the leaf data from backend
  2. Computing the Merkle proof path
  3. Verifying against the root_hash stored on-chain
```

## 8. NFT Market Flow (Kiosk — pending full implementation)

```
Seller
  │  must be is_trading = false
  │
  ├── Force Walrus sync (experience up to date)
  │     ExperienceEngine → blob → Walrus
  │     blob_id → written to Panda's dynamic_field
  │
  ├── Call market::list(kiosk, cap, panda, price)
  │     kiosk::place_and_list(panda, price)
  │     TransferPolicy<Panda> enforces 2–5% royalty
  │
Buyer
  │
  └── Call market buy function
        transfers SUI (price - royalty) to seller
        transfers royalty to policy owner
        kiosk::purchase → panda transferred to buyer
        buyer loads experience from Walrus blob_id
```

`market.move` currently stubs with `abort 0`; the Kiosk PTB logic is next in the implementation queue.

## 10. Key Business Rules (locked decisions)

| Rule | Value | Source |
|---|---|---|
| Execution threshold | `final_score > 0.65` | PRD §C12 |
| Observe zone | `0.40 – 0.65` | PRD §C12 |
| Ignore threshold | `< 0.40` | PRD §C12 |
| Emotion stability | derived from `patience`, not a separate axis | PRD §C9 |
| Merkle batch size | 50 trades | PRD §C1 |
| Win rate | computed in PostgreSQL, not stored on-chain | PRD §C11 |
| Strategy ghost weight | old strategy influence decays after switching | PRD §C7 |
| All computation | server-side only, frontend displays only | PRD §C4 |
| Simulation data source | DeepBook (testnet) | PRD §C5 |
| Experience storage | PostgreSQL + Walrus, no local SQLite | PRD §C2 |
