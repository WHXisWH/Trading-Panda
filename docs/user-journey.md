> Version 1.0 · 2026-06-17  
> Source: `docs/PRD.md` v3.1 Autonomous Agent Wallet  
> Purpose: turn the PRD into screen-level journeys and prototype navigation.

---

## 1. Product Journey Principle

TradingPanda is not a generic trading bot UI. The user journey must constantly reinforce one idea:

```text
The user is training a Move-constrained autonomous trading wallet.
```

The Panda can watch markets and decide autonomously, but it can only act inside user-signed boundaries:

```text
Panda NFT = agent identity
PandaVault = bounded training account
TradingPolicy = risk collar
Agent Signer = authorized automated paw print
Training Ledger = mainnet-price paper execution truth
Chain Proof Moment = selected testnet PTB proof
Trade Fact = evidence record
Skill Memory = reviewed learning
```

---

## 2. Journey Overview

| ID | Journey | User goal | Core screen | System promise |
|---|---|---|---|---|
| J0 | Connect And Understand | Understand the product and connect identity | Landing / Connect | User sees that Panda cannot control the whole wallet |
| J1 | Mint Panda Identity | Create the autonomous agent identity | Mint Panda | Panda NFT is minted and immutable personality is generated |
| J2 | Create Agent Wallet | Give the Panda a bounded wallet and risk collar | Agent Wallet Setup | PandaVault and TradingPolicy are created by user-signed transactions |
| J3 | Feed Strategy | Teach the Panda what style to practice | Strategy Builder | Strategy is validated, versioned, and linked to the Panda |
| J4 | Start Training | Let the Panda watch real markets and act in the ledger | Training Ledger Dashboard | DeepBook mainnet data drives autonomous decisions and paper execution |
| J5 | Inspect Decisions | See why the Panda bought, sold, held, or got blocked | Decision Timeline | Every OrderIntent has policy, market, and reasoning snapshots |
| J6 | Prove On Chain | Show selected autonomous actions as real testnet PTBs | Chain Proof Panel | Agent Signer submits policy-checked PandaCoin demo execution |
| J7 | Review And Learn | Understand wins/losses and update skills | Review Journal | Closed trades produce evidence-backed reviews and Skill Memory updates |
| J8 | Control Risk | Pause, revoke, or tighten the Panda | Emergency Controls | Policy changes block both backend execution and Move demo execution |

## 3. Primary Happy Path

```text
Visitor
→ Connect wallet / zkLogin
→ Mint Panda NFT
→ Create PandaVault
→ Create TradingPolicy
→ Feed strategy
→ Start Training Ledger
→ Panda monitors DeepBook mainnet
→ Panda creates OrderIntent
→ PolicyGate checks the collar
→ LedgerService executes paper trade
→ TradeFactWriter commits evidence
→ ProofSelector may request Chain Proof Moment
→ ChainExecutionWorker submits testnet PandaCoin PTB
→ ReviewWorker reviews closed outcomes
→ SkillMemoryWorker updates learned rules
→ User sees growth, proof, and safety controls
```

## 4. Detailed Journeys

### J0 — Connect And Understand

| Field | Detail |
|---|---|
| Entry | User opens TradingPanda from campaign, hackathon demo, or shared proof link |
| User question | "Is this AI going to touch my wallet?" |
| Screen needs | Short positioning copy, wallet / zkLogin connect, safety explanation |
| System actions | Create auth nonce, verify wallet or zkLogin session, load existing Pandas |
| Trust cue | "PandaVault is not your whole wallet. TradingPolicy is the collar." |
| Success | User is authenticated and can mint or open existing Panda |
| Failure | Wallet rejected, auth expired, network unavailable |

### J1 — Mint Panda Identity

| Field | Detail |
|---|---|
| Entry | Authenticated user has no Panda or clicks "Mint another Panda" |
| User question | "Who is my agent?" |
| Screen needs | Name, mint explanation, personality reveal, transaction status |
| User action | User signs a Sui transaction containing the mint PTB |
| Chain action | Panda NFT is created; immutable personality is generated by `sui::random` |
| Backend action | Register Panda object, owner, personality, and initial status |
| Success | User sees Panda identity and next step: "Create Agent Wallet" |
| Failure | Mint rejected, object parsing failed, backend registration failed |

### J2 — Create Agent Wallet

| Field | Detail |
|---|---|
| Entry | User owns a Panda but has no active PandaVault / TradingPolicy |
| User question | "How much freedom do I give this Panda?" |
| Screen needs | Budget, allowed pairs, max notional, max daily loss, proof mode, authorized agent address |
| User action | User signs transactions to create PandaVault and TradingPolicy |
| Chain action | Shared `PandaVault` and standalone shared `TradingPolicy` are created |
| Backend action | Mirror policy, vault, and authorized agent metadata |
| Trust cue | Policy loosening always requires a user-signed transaction |
| Success | Panda can enter Training Ledger mode |
| Failure | Policy invalid, signer mismatch, transaction failed |

### J3 — Feed Strategy

| Field | Detail |
|---|---|
| Entry | Panda has wallet setup, but no active strategy or user wants to update strategy |
| User question | "What should my Panda practice?" |
| Screen needs | Strategy templates, rule blocks, optional natural language, validation preview |
| System action | Parse / validate strategy, create strategy version, record ghost influence |
| Trust cue | Agent may suggest changes but cannot grant itself more risk |
| Success | Active strategy is ready for the decision pipeline |
| Failure | Invalid rule, unsupported pair, strategy conflicts with policy |

### J4 — Start Training

| Field | Detail |
|---|---|
| Entry | Panda has active strategy, vault, and policy |
| User question | "Is my Panda actually watching real markets?" |
| Screen needs | DeepBook chart, market health, ledger balance, positions, start/stop training |
| System action | Start PandaActor, consume `market:tick:{pair}`, run decision loop |
| Execution truth | PnL is computed from DeepBook mainnet reference prices |
| Policy rule | Every executable OrderIntent must pass backend PolicyGate |
| Success | User sees decisions, paper trades, and live ledger changes |
| Failure | Market stale, Redis down, policy cache stale, ledger mutation failed |

### J5 — Inspect Decisions

| Field | Detail |
|---|---|
| Entry | Panda emits a decision or execution event |
| User question | "Why did my Panda do that?" |
| Screen needs | Decision timeline, final score, policy snapshot, market snapshot, status |
| System action | Commit OrderIntent and Trade Fact atomically with ledger records |
| Statuses | `DECIDED`, `REJECTED_BY_POLICY`, `PAPER_EXECUTED`, `POSITION_CLOSED` |
| Trust cue | Policy failures are visible, not silently dropped |
| Success | User can explain each buy, sell, hold, or rejection |
| Failure | Incomplete event payload, stale snapshots, missing trade fact |

### J6 — Prove On Chain

| Field | Detail |
|---|---|
| Entry | Trade Fact is eligible for automatic proof or user clicks "Prove on-chain" |
| User question | "Can this Panda really act autonomously on Sui?" |
| Screen needs | Proof eligibility, PTB path, tx digest, policy version, decision hash |
| System action | ProofSelector creates async job; ChainExecutionWorker builds testnet PTB |
| Signer action | Environment-level Agent Signer signs the authorized testnet transaction |
| Move action | `demo_executor` checks TradingPolicy and mutates PandaVault / PandaCoin state |
| Success | `DemoTradeExecuted` event and tx digest attach to Trade Fact |
| Failure | Cooldown, daily cap, policy pause, duplicate proof, testnet PTB failure |

### J7 — Review And Learn

| Field | Detail |
|---|---|
| Entry | SELL reduces or closes a position and realized PnL is known |
| User question | "Did my Panda learn the right lesson?" |
| Screen needs | Win/loss story, original belief, market evidence, hypothesis status, skill update |
| System action | ReviewWorker compares decision reason with market outcome |
| Learning rule | Skill Memory updates only after reviewed outcomes, not raw LLM claims |
| Success | Verified or supported hypothesis creates a new skill version |
| Failure | No realized PnL, weak evidence, contradictory facts, review timeout |

### J8 — Control Risk

| Field | Detail |
|---|---|
| Entry | User wants to stop, tighten, or revoke the Panda |
| User question | "How do I stop the Panda immediately?" |
| Screen needs | Pause, revoke agent, tighten policy, rotate signer status, visible consequences |
| User action | User signs update / pause / revoke transaction |
| System action | Backend policy mirror updates; future Mode 1 and Mode 2 actions are blocked |
| Trust cue | Agent cannot unpause itself or loosen policy |
| Success | Dashboard shows paused or revoked state |
| Failure | Policy update transaction failed, backend mirror lagging, old proof job must be canceled |

## 6. Cross-Journey State Rules

| State | User-visible behavior | System behavior |
|---|---|---|
| No Panda | Show mint path only | Do not start actors |
| Panda minted, no policy | Prompt Agent Wallet Setup | Market viewing may work, execution disabled |
| Policy paused | Show red paused banner | Reject Mode 1 execution and Mode 2 proof |
| Agent revoked | Show signer revoked | ChainExecutionWorker must not submit PTB |
| Market stale | Show degraded market status | PandaActor holds or pauses new decisions |
| Paper trade open | Show unrealized PnL but no skill update | Reviews wait for realized PnL |
| Trade closed | Show realized PnL and review queue | ReviewWorker creates evidence-backed review |
| Proof failed | Show chain failure separate from ledger outcome | Do not roll back paper trade fact |
| Skill updated | Show skill version and evidence | Submit digest periodically |

## 7. Prototype Navigation Requirement

The prototype should be a small static site under the repository root:

```text
prototype/
├── index.html                      # journey overview and navigation only
├── styles.css                       # shared Cyber Panda visual system
├── journey.js                       # shared stepper/tab show-hide behavior
└── journeys/
    ├── mint.html                    # J0-J1 stepper states
    ├── agent-wallet.html            # J2 stepper states
    ├── strategy.html                # J3 stepper states
    ├── training.html                # J4-J5 24h loop stepper states
    ├── chain-proof.html             # J6 auto/manual proof stepper states
    ├── review.html                  # J7 hypothesis lifecycle states
    └── safety.html                  # J8 active state + action tabs
```

Navigation rule:

```text
index.html is the map.
Each journey page is a state machine room.
Every room links back to the map and to peer journeys.
Each step switches both the central UI state and the right-side facts panel.
The right-side panel uses User action / Chain changes / Backend changes / Failure.
```
